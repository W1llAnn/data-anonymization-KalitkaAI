# Схема маркеров и правила консистентности

> Неделя 1, пуш 2 (Р2). Код-форма разделов §7–8 architecture.md. Согласовано с Р5:
  ключи нормализации ниже — это же ключи таблицы соответствий.

## 1. Формат маркера

```
marker    := type "_" number
type      := "PERSON" | "PHONE" | "EMAIL" | "ADDRESS" | "DOC_ID"
number    := 1..N  (сквозная нумерация по типу в рамках ключа user_id + context_id)

regex: ^(PERSON|PHONE|EMAIL|ADDRESS|DOC_ID)_[1-9][0-9]*$
```

Свойства:

- Маркер пишется в верхнем регистре; окружающие пробелы сохраняются как в исходном
  тексте (замена строго спана).
- Нумерация начинается с 1, без пропусков; при повторном упоминании номер
  переиспользуется.

## 2. Нормализация для повторных упоминаний

Повторные упоминания считаются одинаковыми, если совпадает нормализованный ключ:

```python
def normalize(value: str, etype: EntityType) -> str:
    match etype:
        case PERSON:
            # лемматизация ФИО (pymorphy3), нижний регистр, схлопывание пробелов;
            # "Ивану Петрову" и "Иван Петров" → "иван петров"
            return " ".join(lemma(word) for word in value.split()).lower()
        case PHONE:
            # только цифры; ведущая 8 → 7; итог — 11 знаков
            digits = re.sub(r"\D", "", value)
            return "7" + digits[1:] if digits.startswith("8") else digits
        case EMAIL:
            return value.strip().lower()
        case ADDRESS:
            # нижний регистр, разворот сокращений (г/ул/д/кв/обл...), схлопывание пробелов
            return expand_abbreviations(value).lower()
        case DOC_ID:
            # только цифры (СНИЛС/ИНН/паспорт), сохранение длины формата
            return re.sub(r"\D", "", value)
```

Словарь соответствий хранит оба ключа: `marker → original_value` (для восстановления)
и `normalize(original_value) → marker` (для консистентности) — детали схемы у Р5.

## 3. Приоритеты детекторов (гибрид)

Порядок применения при разметке одного текста:

```
1. STRICT_RULES   — телефоны, email, ИНН/СНИЛС/паспорт (regex + контрольные суммы)
2. MODEL          — PERSON, ADDRESS (дообученная BIO-модель)
3. NAME_DICT      — словарь имён + pymorphy3 (страховка recall для PERSON)
```

Разрешение пересечений спанов:

- Спан более высокого приоритета побеждает; при равном приоритете — длиннее.
- Пересечение считается по символам: `a.start < b.end and b.start < a.end`.
- Смежные ADDRESS-спаны (разделённые запятой/соединительным словом) склеиваются
  постобработкой.

## 4. Замена в тексте

```
для каждого итогового спана (слева направо):
    marker = assign_marker(normalize(span.text), span.entity_type)
    text[span.start:span.end] = marker
```

Гарантия: символы вне спанов не изменяются — «полезные числа» и структура текста
сохраняются байт-в-байт (требование ТЗ п.8).

## 5. Восстановление (обратная подстановка, владелец Р5)

- Известный маркер (есть в таблице соответствий по user_id + context_id) → исходное
  значение.
- Неизвестный маркер (нет записи, истёк TTL, придуман моделью) → передаётся как есть.
- Regex распознавания маркеров в тексте ответа: `\b(?:PERSON|PHONE|EMAIL|ADDRESS|DOC_ID)_\d+\b`
  (уже реализован в каркасе `src/anongw/restorer/service.py`).
