# План экспериментов Р2

> Неделя 1, пуш 2 (Р2). Операционализация [docs/training.md](../training.md):
  кто, что, когда и по какому протоколу прогоняет. Все прогоны логируются в
  `eval/reports/experiments.jsonl` и попадают в таблицу отчёта (ТЗ п.1, п.8).

## Протокол (единый для всех участников)

- Данные: одна версия расширенной синтетики Р3; сплит train/dev 90/10; контрольная
  выборка — неприкосновенна до финальной оценки.
- Метрики: span-level precision / recall / F1, macro и по 5 типам.
- Гиперпараметры: сетка из training.md §6 (lr ∈ {3e-5, 1e-4-tiny}, batch 16,
  max_len 512, до 10 эпох, early stopping patience 3, seed 42).
- Бюджет: не более 3 конфигураций на участника линейки.

## Критерии перехода между неделями

- Неделя 2 → 3: rules дают precision ≥ 90% на строгих форматах (иначе чиним regex,
  не идём дальше).
- Неделя 6 → 7: хотя бы один из C1/C2 проходит пороги на dev; если нет — расширение
  синтетики с Р3 (1к → 3к) до запуска C3.
- Неделя 7 (финал): recall ≥ 95% общий, ≥ 90% по каждому типу, precision ≥ 90% на
  контрольной — иначе эскалация по training.md §7 (расширение данных и сетки).

## Артефакты каждого прогона

1. Запись в `eval/reports/experiments.jsonl`: участник, конфиг, версия датасета,
   сид, метрики на dev (и на контроле — для финальных).
2. Чекпойнт в `eval/checkpoints/<id>/` (в git не попадает, `.gitignore`).
3. Короткая заметка об ошибках: топ-категории FP/FN — вход в анализ ошибок недели 8.

## Зависимости от других ролей

- Р3: версии датасета (150 → 300 → расширенная синтетика → контроль 100+).
- Р1: `train.py` и конвертер BIO лежат в `src/anongw/` — ревью контрактов.
- Р6: скрипт оценки `eval/` — единый подсчёт метрик для всех участников.
