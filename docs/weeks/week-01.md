## Пуш 0 — постановочный (уже сделан, роль Р1)

Создана ветка `week-01`, добавлены `docs/git-workflow.md` (полная последовательность пушей и мержей на все 11 недель) и этот файл задач.

## Пуш 1 — Р1, тимлид / Backend-core → `week-01-r1-infra`

Задачи:
- Структура `src/anongw/` (пакеты `api`, `anonymizer`, `restorer`, `files`, `mapping`, `upstream`, `config.py`) по [docs/architecture.md §12](../architecture.md).
- FastAPI-приложение с эндпоинтом `GET /health` (200, `{status: ok}`).
- `Dockerfile` + `docker-compose.yml`: два контейнера — сервис и заглушка mock (порты зафиксировать).
- CI (GitHub Actions): ruff + mypy + pytest на каждый PR.
- `pyproject.toml` с зависимостями каркаса (fastapi, uvicorn, httpx, pydantic).
- **Protocol/Pydantic-схемы межкомпонентных интерфейсов**: `Anonymizer`, `Restorer`, `MappingStore`, `FileExtractor`, `UpstreamClient` — контракты, на которых строится вся параллельная работа.
- Организационное: доска задач, шаблон PR, правила ревью.

DoD роли: `docker compose up` поднимает оба контейнера, `/health` отвечает, CI зелёный, схемы слиты и объявлены команде.

## Пуш 2 — Р2, ML-инженер → `week-01-r2-nlp-plan`

Задачи:
- Техобзор `docs/ml/research.md`: Natasha vs DeepPavlov vs правила — качество на русском, размер, лицензии, локальный запуск без GPU.
- Схема маркеров и правил консистентности (черновик §7–8 architecture.md в код-форме: форматы маркеров, приоритеты типов).
- План экспериментов по [docs/training.md](../training.md): что и в каком порядке прогоняем.

DoD роли: документ обзора с рекомендацией; схема маркеров согласована с Р5.

## Пуш 3 — Р3, Data-инженер → `week-01-r3-dataset-schema`

Задачи:
- Шаблоны генерации трёх жанров: письма, документы, фрагменты интервью.
- Скрипт-скелет генератора `dataset/generator/` (CLI, сид, выход в JSONL).
- Схема JSONL-разметки (id, текст, тип, границы спана, id лица) и CSV-реестра — примеры по 3 записи каждой.

DoD роли: генератор выдаёт 10 примеров-образцов, схема согласована с Р2 (под метрики) и Р6 (под контрольную выборку).

## Пуш 4 — Р4, инженер файлов → `week-01-r4-files-proto`

Задачи:
- Прототип извлечения текста из TXT: детекция кодировок (UTF-8/UTF-16/CP1251).
- Прототип DOCX через python-docx: параграфы + таблицы, без метаданных.
- Черновик правил валидации `input_file`: расширение, размер, отказ для PDF/DOC/изображений.

DoD роли: прототип на 5 тестовых файлах отдаёт чистый текст; список поддерживаемых частей DOCX — черновиком.

## Пуш 5 — Р5, инженер восстановления → `week-01-r5-mapping-schema`

Задачи:
- DDL SQLite (`mappings`) по [docs/architecture.md §6](../architecture.md) + миграция/инициализация.
- План TTL-очистки: фоновая задача, интервал, настройка срока.
- Черновик алгоритма вывода `context_id` из явно переданной истории.

DoD роли: схема БД создается скриптом; алгоритм `context_id` согласован с Р1 и Р2.

## Пуш 6 — Р6, QA → `week-01-r6-test-plan`

Задачи:
- Каркас `tests/` (pytest, pytest-asyncio, маркеры `integration`/`unit`), проводки в CI.
- Черновик mock-LLM: эндпоинт `/v1/responses`, детерминированные ответы, **запись всех входящих запросов** (для тестов утечек).
- План 30+ интеграционных проверок по категориям [docs/sprints.md, приложение](../sprints.md) — согласование с командой.

DoD роли: mock поднимается из compose; план проверок утверждён; первый smoke-тест зелёный.
