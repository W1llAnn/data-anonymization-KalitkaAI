# План интеграционных проверок (37)

> Неделя 1, пуш 6 (Р6). Черновик на утверждение командой (DoD недели).
> Категории согласованы с приложением [docs/sprints.md](../sprints.md).
> Колонка «неделя» — когда проверка становится выполнимой по плану спринтов.

## Как устроены тесты

- Маркер `unit` — изолированные проверки компонентов (запуск: `pytest -m unit`).
- Маркер `integration` — сквозные проверки с mock-LLM на реальном HTTP
  (`pytest -m integration`). Фикстуры: `mock_llm_url` (сессия), `service_client`.
- Mock-LLM (`tests/mock_llm/app.py`) пишет payload и заголовок авторизации в
  `/__recorded` — на этом строятся проверки утечек и раздельных ключей.
- Условие всех утечек: известные исходные значения отсутствуют в перехваченном
  запросе к модели и в рабочих логах (ТЗ п.9).

## Требования к каждой проверке при реализации

1. Известные ПДн фиксируются в тесте как константы; после прогона — их отсутствие
   в `/__recorded` (payload и заголовки) и в захваченном логе.
2. Каждая проверка идентифицируется номером реестра в имени теста
   (`test_034_no_pii_in_upstream_request`).
3. Перед финальным прогоном недели реестр сверяется с фактическим набором тестов;
   пропуски помечаются и обосновываются.
