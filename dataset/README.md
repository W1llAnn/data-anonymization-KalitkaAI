# Датасет (синтетический)

Все персональные данные в примерах вымышленные, генерируются шаблонами.
Реальные базы и документы не используются (ТЗ, раздел «Датасеты»).

## Структура

```
dataset/
├── generator/            # генератор, пулы, шаблоны, валидатор, экспорт файлов
├── samples/              # образцы недели 1 (10 примеров)
├── files/                # примеры недели 3 файлами: 7 TXT + 3 DOCX
└── train/
    ├── train_w2.jsonl    # обучающая выборка недели 2: 75 примеров (seed 202)
    ├── train_w3.jsonl    # обучающая выборка недели 3: 150 примеров (seed 303)
    ├── control_w3.jsonl  # контрольная подвыборка недели 3: 30 примеров (seed 304,
    │                     #   отдельные шаблоны control_*, не участвуют в обучении)
    ├── train_w4.jsonl    # обучающая выборка недели 4: 300 примеров, 1141 сущность,
    │                     # 12 шаблонов (seed 404); 30 файлов TXT/DOCX в dataset/files
    ├── train_1k.jsonl    # расширенная синтетика для обучения: 1000 примеров,
    │                     # 3488 сущностей (seed 1001, ветка model-c1)
    ├── registry_*.csv    # реестры выборок
    └── bio/              # производные BIO-файлы (eval/convert_to_bio.py), в git не попадают
```

Файлы `dataset/files/` (30 шт.: 21 TXT + 9 DOCX) всегда соответствуют последней
обучающей выборке (`train_w4`); формат каждого экспортированного примера
отмечен в его реестре. Требование ТЗ «не менее 30 примеров файлами» выполнено.

Контрольные шаблоны (`control_letter_confirm`, `control_document_proxy`,
`control_interview_home`) не пересекаются с обучающими — требование ТЗ
(проверяется тестом для всех обучающих выборок).
Полная контрольная выборка 100+ примеров — неделя 5.

## Запуск генератора

```bash
python -m dataset.generator --count 150 --seed 303 --split train \
    --out dataset/train/train_w3.jsonl --registry dataset/train/registry_w3.csv \
    --export 10 --export-dir dataset/files
python -m dataset.generator --count 30 --seed 304 --split control \
    --out dataset/train/control_w3.jsonl --registry dataset/train/control_registry_w3.csv
python -m dataset.generator.validate dataset/train/train_w3.jsonl
```

Параметры: `--count`, `--seed` (воспроизводимость), `--split train|control`
(control генерирует только контрольные шаблоны), `--out`, `--registry`,
`--export N` + `--export-dir` (7 TXT + 3 DOCX на каждые 10; формат отмечается
в реестре). Один и тот же сид даёт один и тот же набор.

Валидатор проверяет: уникальность id, границы спанов, совпадение текста спана,
один entity_id → один тип в пределах примера, отсутствие пересечений спанов.
Валидация встроена в CI после smoke-генерации.

## Валидность номеров

ИНН-10/ИНН-12 и СНИЛС генерируются с корректными контрольными суммами,
банковские карты — с валидной суммой Луна (`dataset/generator/pii_gen.py`) —
детекторы строгих форматов находят их все. Расчётные счета — 20 цифр с
реалистичным префиксом; детектор требует контекстного слова «счёт». Паспорт
российской контрольной суммы не имеет, поэтому детектируется по формату
«4 цифры, пробел, 6 цифр».

## Схема JSONL (annotations)

Одна строка — один пример:

```json
{
  "id": "ex_0000",
  "genre": "letter",
  "template": "letter_contact",
  "text": "Здравствуйте, Ивану Петрову!...",
  "entities": [
    {"start": 13, "end": 25, "entity_type": "PERSON", "entity_id": "e1", "text": "Ивану Петрову"}
  ]
}
```

| Поле | Описание |
|---|---|
| `id` | уникальный идентификатор примера |
| `genre` | жанр: `letter` / `document` / `interview` |
| `template` | имя шаблона-источника (для реестра и отделения контрольных) |
| `text` | текст примера |
| `entities[].start`, `entities[].end` | полуинтервал [start, end) в символах `text` |
| `entities[].entity_type` | PERSON / PHONE / EMAIL / ADDRESS / DOC_ID |
| `entities[].entity_id` | одинаковый для повторных упоминаний одного лица/объекта |

Схема согласована: Р2 — конвертация в BIO по `start/end` (docs/ml/marker-scheme.md);
Р6 — отбор контрольной выборки по `template`.

## Схема CSV-реестра (registry)

`example_id, genre, template, format, split, n_entities, PERSON, PHONE, EMAIL, ADDRESS, DOC_ID`

`format` — `text` сейчас, `txt`/`docx` появятся с выгрузкой файлов (неделя 2).
`split` — принадлежность к выборке: `train` / `control`.

## Текущие ограничения скелета (неделя 1)

- Падежные формы имён заданы парами в `pools.py`; склонение через pymorphy3 —
  при расширении.
- Контрольные суммы ИНН/СНИЛС не валидируются генератором (номера синтетические);
  валидация — на стороне правил Р2.
- DOC_ID в шаблоне справки помечается единым типом; разделение на подтипы
  (паспорт/СНИЛС/ИНН) в скоуп типа не входит — различаются форматом.
